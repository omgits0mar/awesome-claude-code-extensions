# Licensing

Public GitHub source is not automatically open source. Without an applicable license, the default is generally “all rights reserved,” even when the repository is readable or free to use.

## Catalog policy

- Prefer projects with an OSI-approved license covering the exact linked artifact.
- Record `license_verified: true` and `license_checked_at` only after checking the upstream license, exact version, and artifact scope.
- Use `license_verified: false` for inherited records awaiting review.
- Do not assume a root license covers vendored files, external marketplace sources, generated bundles, or nested subdirectories.
- Link to upstream instead of copying plugin code or long README passages.
- Preserve upstream copyright, license, NOTICE, and attribution requirements for anything vendored.

Descriptions are short factual summaries, but some are sourced or normalized from attributed upstream metadata. They are not relicensed by this repository. Source-list provenance is retained in every record and in [`NOTICE.md`](../NOTICE.md).

## This repository

- Original catalog structure, annotations, and prose: [CC0-1.0](../LICENSE).
- Scripts, workflows, and schemas: [MIT](../LICENSE-CODE).
- Imported source snapshots, names, URLs, and upstream-derived descriptions: excluded from the CC0 dedication and governed by their source terms; see [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md).
- Linked projects: their own upstream licenses and trademarks.

This is practical project policy, not legal advice.
